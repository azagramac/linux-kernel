# 🐧 Linux Kernel 7.3

-   **📅 Release date:** 18 October 2026
-   **🌿 Series:** 7.x mainline
-   **📦 Type:** Mainline feature release
-   **✅ Status:** Released

Linux **7.3** is a mainline kernel release focused on scheduler
extensibility, memory management, graphics, filesystem performance,
file-descriptor-based isolation, and I/O efficiency. It introduces or
completes substantial functionality in `sched_ext`, `userfaultfd`, FUSE
over `io_uring`, `binfmt_misc`, and the new `failfs`/`fchroot()`
sandboxing model.

The release also brings improvements to Btrfs and ext4, enhanced SMB
server capabilities, storage and networking updates, architecture
support, and a broad set of driver changes.

> 📌 **Linux 7.3 combines new kernel interfaces with performance and
> resource-management improvements, particularly in scheduling, GPU
> memory management, filesystems, and asynchronous I/O.**

# ⚙️ Scheduler / `sched_ext`

## BPF sub-schedulers per cgroup

Linux 7.3 completes a major part of the `sched_ext` work, allowing
individual cgroups to be managed by their own BPF-based sub-schedulers.
This makes it possible to build hierarchical scheduling policies instead
of requiring one scheduler policy to control every workload.

-   ⚙️ Allows cgroups to use their own BPF scheduler.
-   🧩 Adds capability-based CPU delegation from parent schedulers to
    child schedulers.
-   🔐 Makes delegation of scheduling capabilities explicit and enforces
    it across scheduler paths.
-   🧠 Adds flexibility for cgroup v2 scheduling policies.
-   🔧 Makes the `ops.cgroup_set_bandwidth()` hook sleepable, allowing
    operations such as memory allocation from that hook.

## Cgroup scheduling and latency

-   ⚙️ Adds multiple cgroup weight-distribution modes: `up`, `max`,
    `concur` and `tasks`.
-   🧠 Uses `concur` as the default mode, prioritising accurate weight
    distribution at additional computational cost.
-   🔧 Changes cgroup scheduling to use a single runqueue.
-   ⚡ Improves latency for tasks with shorter time slices by adjusting
    or reducing protection of running tasks where appropriate.
-   🧩 Fixes cluster scheduling when CPU capacity is asymmetric.
-   🛠️ Improves fair-scheduler balancing, including preference for fully
    idle cores during NOHZ balancing.
-   🧹 Includes additional scheduler and `sched_ext` correctness fixes.

# 🧠 Memory Management

## GPU memory and `dmem` cgroups

Linux 7.3 improves how GPU memory protection behaves when applications
compete for limited VRAM. Under contention, the kernel can evict
unprotected buffers from a memory domain to make room for protected
allocations, rather than immediately falling back to system RAM
accessible through the GPU (GTT).

-   🎮 Improves memory-protection behaviour for AMDGPU and Intel Xe.
-   🧠 Adds reclaim behaviour when `dmem` limits are lowered below
    current usage.
-   🔄 Allows reclaiming VRAM into GTT in applicable cases.
-   🛡️ Better respects low, minimum and maximum memory settings in
    supported scenarios.
-   🎯 Aims to reduce allocation ping-pong and improve behaviour on GPUs
    with limited VRAM.

These changes are especially relevant when several applications compete
for GPU memory. Actual benefits depend on the driver, hardware, cgroup
configuration and workload.

## DAMON

-   📊 Introduces data-attribute-oriented monitoring and region
    management.
-   🧠 Allows monitoring policies to prioritise attributes such as page
    size or cgroup membership instead of relying only on
    access-frequency tracking.
-   ⚙️ Uses weighted probe-hit counters to guide monitoring-region
    adjustment.
-   🔧 Provides more flexible monitoring for workloads where data
    attributes matter more than access tracking alone.

## Memory reclaim and allocation

-   🧠 Improves reclaim behaviour when a memory cgroup is being removed
    while synchronous reclaim is in progress.
-   🛡️ Adds an opt-in `vm.panic_on_unrecoverable_memory_failure` control
    for unrecoverable errors involving kernel-owned pages.
-   🔧 Fixes reclaim storms and spurious out-of-memory events associated
    with `vm.defrag_mode=1` under high memory pressure.
-   🧹 Removes redundant LRU-drain operations in anonymous-folio reuse
    paths.
-   🛠️ Simplifies page allocator APIs and allocation flags.
-   🧩 Updates Maple Tree locking and internal code.
-   🔧 Refines page-table and VMA walking interfaces.
-   🧠 Adds further memory-accounting, allocation and error-handling
    fixes.

# 🎮 Graphics / DRM

## AMDGPU

Linux 7.3 includes graphics-driver changes covering GPU memory
management, context handling, display colour processing, performance and
resource lifetime.

### VRAM management

-   🎮 Works with `dmem` cgroup improvements to better protect
    allocations under VRAM contention.
-   🧠 Improves reclaim decisions when memory limits or protection
    levels require buffers to be evicted.
-   🔄 Helps reduce unnecessary fallback to GTT in supported contention
    scenarios.

### Driver performance and resource management

-   ⚡ Reduces CPU overhead in GPU job submission.
-   🧹 Removes an unnecessary buffer-object-list mutex.
-   🧩 Replaces legacy IDR-based buffer-object list handling with
    XArray.
-   🔧 Simplifies context and buffer-object management.
-   🧠 Caches invariant IP checks and avoids repeated calculations in
    selected paths.
-   💤 Reduces unnecessary idle-worker re-arming.
-   🛡️ Fixes potential use-after-free and NULL-pointer dereference
    issues in context/pstate handling.
-   📦 Reduces compiled driver size by moving selected decisions from
    macros to driver-initialisation checks.
-   🔧 Adds and refines GPU debug, RAS and device-management paths.

### AMD display

-   🎨 Fixes HDR gradient banding in supported display-generation paths.
-   🧮 Refines degamma and transfer-function lookup-table segmentation.
-   🖥️ Improves handling of subsampled formats and AMD-specific display
    colour properties.
-   🔧 Fixes warnings caused by missing blend-mode properties on
    supported display hardware.
-   🛠️ Includes additional display-pipeline and colour-management
    corrections.

## Intel i915 / Xe

-   🖥️ Includes display-code fixes involving enum storage and transcoder
    masks.
-   🎮 Integrates `dmem`-related eviction improvements for supported GPU
    memory paths.
-   🔧 Adds or updates GPU health and error-counter interfaces in
    relevant Xe paths.
-   ⚡ Includes performance and power-management refinements.
-   🧹 Fixes selected resource-lifetime and display handling issues.

## Nouveau

-   🛠️ Simplifies parts of the Nouveau client code.
-   🔧 Includes general DRM and GPU-driver maintenance.

## Raspberry Pi V3D / VC4 and other DRM drivers

-   🎮 Refactors V3D submission handling into a clearer job-chain
    abstraction.
-   🔧 Improves validation of submission handles and failure paths.
-   🧵 Improves performance-monitor locking and cross-queue
    serialisation.
-   🧹 Fixes V3D job, buffer-object and fence handling.
-   💤 Refines runtime power management in V3D/VC4.
-   🛠️ Includes fixes and cleanups in Panfrost, Panthor, Etnaviv and
    shared DRM scheduling code.
-   🔧 Fixes memory leaks in KMS atomic modesetting and selected KUnit
    tests.

# 📁 Filesystems

## 🐧 Btrfs

Linux 7.3 contains several performance improvements for Btrfs.

-   ⚡ Restores Direct I/O performance affected by previous changes.
-   💾 Removes an unnecessary one-jiffy delay in certain logging
    workloads on non-SSD storage.
-   🚀 Improves `fsync()` throughput in supported cases, including
    filesystems using the no-holes feature.
-   🧠 Replaces an XArray-based tracking mechanism with a local LRU list
    for inhibited extent buffers.
-   🔧 Includes additional filesystem correctness and maintenance fixes.

The reported performance gains apply to the specific workloads and
configurations addressed by the changes; they should not be interpreted
as a universal speed increase for every Btrfs workload.

## 🗂️ ext4

-   ⚡ Improves parallel Direct I/O writes.
-   💾 Improves `fallocate()` performance by avoiding unnecessary work.
-   🔧 Fixes a buffered-write performance regression.
-   🧹 Improves large-folio write handling and avoids unnecessary
    traversal in applicable paths.

## 📦 FUSE and `io_uring`

-   ⚡ Adds buffer-pool support for FUSE over `io_uring`.
-   🧠 Allows the kernel to assign request payload memory more
    efficiently.
-   🚀 Adds zero-copy paths so FUSE servers can access client pages or
    page-cache folios without an intermediate copy.
-   🔐 The zero-copy functionality has privilege and buffer-pool
    requirements, including `CAP_SYS_ADMIN`.
-   🛠️ Includes related FUSE and VFS maintenance.

## 🛡️ `failfs`, `fchroot()` and filesystem isolation

Linux 7.3 introduces `failfs`, a pseudo-filesystem whose operations fail
with `EOPNOTSUPP`, and the new `fchroot()` system call.

-   🔐 `fchroot()` changes a process root using a directory file
    descriptor rather than resolving a pathname again.
-   🧩 Avoids a pathname re-resolution window between selecting the
    target and changing the root.
-   🛡️ Works with file-descriptor-based interfaces such as `O_PATH` and
    detached mount trees.
-   🔒 `failfs` can be used to make absolute-path lookups fail, allowing
    a process to rely on explicitly held directory file descriptors.
-   🧠 Complements the existing `nullfs` concept with different
    semantics: operations are unsupported rather than simply observing
    an empty directory.

These interfaces are intended for specialised isolation and sandboxing
designs. They do not automatically sandbox an application without
appropriate userspace setup.

## `binfmt_misc`

-   🧩 Adds BPF-backed binary handlers.
-   ⚙️ Allows a BPF program to participate in matching a binary and
    selecting its interpreter.
-   📦 Supports more flexible interpreter selection at execution time
    rather than requiring a fixed interpreter string at registration.
-   🛠️ Useful for distribution and runtime designs that need relocatable
    binaries or policy-driven interpreter selection.

## SMB / CIFS and ksmbd

-   🌐 Adds opt-in Apple Time Machine support to the SMB server.
-   🍎 Implements protocol and metadata compatibility needed by macOS
    backup workflows.
-   🔐 Adds or improves SMB3 request replay and per-share encryption
    capabilities.
-   🧩 Implements the SMB2 command-sequence window to validate
    message-ID ranges and prevent invalid requests or same-channel
    replays.
-   🔒 Adds SMB Direct RDMA encryption support.
-   🔧 Includes additional SMB server and client correctness fixes.

## NTFS / NTFS3

-   💾 Adds optional read support for Windows System Compression (WOF)
    in NTFS.
-   🧩 Handles WOF reparse metadata and compressed data chunks.
-   📦 Adds kernel-side decompression support for relevant XPRESS and
    LZX formats.
-   🔧 Adds basic alternative-data-stream support to NTFS3.
-   🛡️ Improves compression error propagation and metadata handling.

## Other filesystems and VFS

-   🧹 Includes additional VFS lookup, mount, writeback and superblock
    updates.
-   🔧 Updates F2FS allocation, flush, metadata and interrupt handling.
-   🛠️ Includes changes across XFS, GFS2, OverlayFS, HFS, NILFS2,
    fscrypt and other filesystem components.
-   📦 Removes the obsolete EFS and FreeVxFS filesystem implementations.
-   🧵 Separates kernel-thread filesystem state from PID 1's filesystem
    state.
-   🔧 Includes further FAT, iomap and cachefiles maintenance.

# 💽 Block Layer / Storage

## Block I/O

-   💾 Adds `RWF_DONTCACHE` support for block devices.
-   ⚙️ Lets applications choose per request whether data should avoid
    remaining in the page cache, rather than relying exclusively on
    Direct I/O.
-   🧠 Can be useful for databases and applications that mix
    cache-friendly and cache-bypassing operations.
-   🔧 Reduces queue freeze/unfreeze overhead in NBD connection setup.
-   🛠️ Improves block-layer statistics and selected request-handling
    paths.

## NVMe / ublk / NBD

-   💽 Adds namespace-level debug information for NVMe target
    reservation state.
-   🛠️ Improves NVMe host-driver analysis and context checking.
-   ⚡ Optimises `ublk` I/O descriptor paths.
-   🔧 Includes additional NBD, NVMe and block-layer cleanup.

## Other storage

-   💾 Includes updates across SCSI, device-mapper-related paths, F2FS
    and storage drivers.
-   🔧 Improves error handling, resource cleanup and device-specific
    compatibility.

# 📌 Linux 7.3 --- Summary

Linux **7.3** is a mainline feature release with major work in
**scheduler extensibility, GPU memory management, filesystem
performance, isolation primitives and asynchronous I/O**.

The most notable changes are:

> ⚙️ **`sched_ext` and cgroup scheduling** · 🎮 **GPU VRAM management**
> · 🧠 **DAMON and memory reclaim** · 📁 **Btrfs/ext4 performance** · 🔐
> **`failfs` and `fchroot()`** · ⚡ **FUSE over `io_uring`** · 🌐 **SMB
> server improvements** · 💽 **`RWF_DONTCACHE`**

For AMD Ryzen and Radeon systems, the most directly relevant areas are
AMDGPU/DRM improvements, GPU-memory handling, and scheduler changes.
Linux 7.3 also introduces new kernel interfaces that may require
corresponding userspace support before applications can benefit from
them.

This document is a structured overview of selected upstream changes, not
a replacement for the complete upstream changelog. Individual features
may depend on hardware, configuration, permissions, and userspace
support.
